## Restore, spawn, and readiness sequence

1. Persistence fully loads and validates a candidate archive and builds a new session scope.
2. The coordinator starts the candidate and raises `SessionStopping(previous)` before
   `SessionStarted(candidate)` to adapters.
3. Old Player NetworkObjects are despawned. Only a PlayerId present in the restored Registry can be
   rebound to a live connection; duplicate aliases are rejected.
4. With `Terrain == null`, spawn lookup searches the restored `WorldStorageSnapshot` in stable
   column order, requires a solid floor, and requires non-liquid headroom.
5. Snapshot completeness creates/replaces the client WorldCore. `WorldViewBridge` rebuilds current
   collider meshes and only then emits versioned WorldReady.
6. `PlayerSpawner` requires authenticated scene presence, matching client WorldReady, and server
   collision readiness before registering the Rigidbody/NetworkObject and spawning.
